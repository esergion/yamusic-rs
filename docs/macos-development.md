# macOS: устройство и проверка

## Разработка в форке

macOS-порт сопровождается в `esergion/yamusic-rs`, ветка `macos-support`.
Оригинальный `SpolzerMod/yamusic-rs` используется как upstream для получения изменений;
macOS-разработка и её проверки выполняются в форке. Изменения не отправляются
в оригинальный проект через pull request без отдельного решения владельца форка.

При локальной работе `origin` указывает на форк, `upstream` — на оригинал.
`.github/workflows/macos.yml` проверяет push в `macos-support` и `main`, а также PR
внутри форка. Он собирает и проверяет локальную .app, не загружая бинарники в артефакты
или релизы. Windows/Linux workflow остаётся отдельным.

Bundle ID и имена записей Keychain сохранены для совместимости с уже установленной
локальной сборкой и сохранённым входом. Метаданные Cargo, ссылка «О приложении» и
источник проверки обновлений указывают на форк.

## Системная интеграция

`src/sys/macos/mod.rs` сохраняет общий интерфейс `sys`. `window.rs` отвечает за окно,
тему и рабочую область экрана; `instance.rs` — за повторный запуск через Unix-сокет;
`commands.rs` — за доставку событий в Slint и время жизни интеграций;
`media.rs` — за снимки состояния Now Playing; `autostart.rs` — за ServiceManagement.

AppKit, MediaPlayer и ServiceManagement реализованы в `native/*.m`. `build.rs`
компилирует их системным Clang с ARC и включает статическую библиотеку в основной
бинарник. Узкий C ABI описан в `native.rs`, `media.rs` и `autostart.rs`. Нативный код
синхронно копирует буферы Rust; метаданные передаются JSON без токенов и данных аккаунта.

`MacIntegration` создаётся в главном потоке, остаётся живым весь event loop и явно
уничтожается до `process::exit`. При уничтожении отзываются отложенные команды,
восстанавливается класс NSApplicationDelegate, удаляются observers и MediaPlayer targets, отменяется загрузка
обложки. События приходят через `Weak::upgrade_in_event_loop`, не удерживая окно.

Slint 1.18.1 использует прямой winit backend с `with_default_menu_bar(false)`, чтобы
встроенное меню не перезаписывало меню приложения при активации окна. winit 0.30.13
фактически регистрирует WinitApplicationDelegate (публичная документация этой версии
утверждает обратное). Мост проверяет конкретный класс и временно расширяет тот же объект
динамическим подклассом через публичный Objective-C runtime. Данные, методы запуска и
проверка isKindOfClass winit сохраняются. При завершении исходный класс восстанавливается;
неизвестный делегат не заменяется. Регрессия покрыта tests/macos_bridge.m. Окно скрывается без уничтожения winit window; callback закрытия
возвращает KeepWindowShown, что запрещает стандартное уничтожение Slint window.

Play/Pause — идемпотентные команды аудиопотока. Now Playing обновляется при смене
метаданных, состояния и скачке позиции, а не каждый кадр. Обложки загружаются отдельно,
старые запросы отменяются; поколение интеграции и track ID защищают от запоздавших ответов.

Автозапуск не записывает LaunchAgent и не регистрируется сам. SMAppService.mainAppService
используется из постоянной `.app` в /Applications или ~/Applications. Состояние требует
различать disabled, enabled, requiresApproval, notFound и недоступность вне установленной
.app. Ошибки отображаются в настройках. Используется только ad-hoc подпись.

## Проверка

Среда разработки: Apple Silicon, macOS 27.2.1, Rust 1.100. Минимальный deployment target
нативного моста и пакета — macOS 13.0; старые macOS и Intel требуют отдельной проверки.

Автоматические проверки:

```sh
cargo clippy --release --all-targets --locked -- -D warnings
cargo test --release --locked
cargo build --release --locked
python3 tools/macos-app.py
sh tools/test-macos-native.sh
codesign --verify --deep --strict "target/macos/Яндекс Музыка RS.app"
```

Unit-тесты покрывают отмену отложенных команд, идемпотентность Play/Pause, обновление
Now Playing при перемотке и паузе, обработку нечисловых позиций и статусы ServiceManagement.
Нативные файлы собираются с `-Wall -Wextra -Werror`.

После пересборки с ad-hoc подписью macOS может повторно запросить доступ к сохранённым
токенам в Keychain. Подтвердите запрос в системном диалоге: пока он ожидает ответа,
чтение конфигурации при запуске блокируется и окно приложения ещё не появляется.
Скрипт упаковки не использует Developer ID и не меняет разрешения Keychain.

Ручной чек-лист для новой сборки:

- Вход, воспроизведение и сохранение входа после перезапуска (проверены пользователем
  на исходном macOS-порте; повторить после нативной интеграции).
- Крестик / Cmd+W → Dock / повторный запуск; Cmd+Q; Cmd+H; Cmd+M; Cmd+,.
- Полноэкранный режим, мини-плеер и возврат размера; редактирование текста через меню.
- Системная тема, Retina, перенос между мониторами, отключение монитора.
- Выбор и отмена папки/изображения с возвратом фокуса.
- Now Playing, обложка, Play/Pause/Next/Prev, перемотка, конкуренция с другим плеером.
- Автозапуск: регистрация, системное разрешение, настоящий выход/вход в macOS,
  отключение из приложения и из системных настроек, перенос/обновление .app.
- Сон/пробуждение, переключение аудиовыхода. Аудиодвижок за пределами команд Pause/Resume
  и эквалайзер не менялись; аппаратные проверки не подменяются unit-тестами.

Не заявлять пройденными ручные проверки без наблюдаемого результата. Developer ID,
нотарификация и выпуск бинарных релизов не входят в эту работу.

## Результаты локального прогона

На macOS 27.2.1 arm64 прошли Clippy с запретом предупреждений, 18 Rust-тестов
(3 существующих сетевых теста пропущены), нативный тест делегата и метаданных
MediaPlayer, release-сборка и проверка ad-hoc подписи. Mach-O сообщает minos 13.0.

В запущенной .app наблюдались нативные кнопки/меню, открытие настроек через Cmd+,
системный диалог выбора папки и отмена, переход в мини-плеер и возврат через меню,
загрузка трека и состояние «Пауза» в меню, остановка воспроизведения через меню,
полное завершение процесса через Cmd+Q. Вход сохранился от предыдущей сборки. На финальной сборке также проверены
Cmd+A → Backspace в поиске, вход/выход из системного fullscreen и возврат исходного
размера после мини-плеера. В fullscreen пункт мини-плеера недоступен, в мини-плеере
отключены системный и собственный пункты fullscreen; сочетание Ctrl+Cmd+F не растягивает
мини-плеер на весь экран.

Настоящий выход/вход в macOS, системное разрешение автозапуска, аппаратные
медиаклавиши, несколько аудиоустройств и отключение монитора требуют отдельной
проверки пользователем. Автоматизация окна сама активирует приложение, поэтому
наблюдение через неё не является независимой проверкой скрытого состояния окна.
